# Handoff: authored not-established identities (issue #32)

Audience: redact-secret-benchmarks (#664, #665, #666). Public synthetic development only;
no protected corpus, key, policy activation or authority change. The semantic decision is
[ADR 0017](../adr/0017-not-established-type-identity-and-schema-1-3.md).

## What changed for the 156 memberships

The 156 of 1,188 population memberships whose authored identity is `not-established`
(four populations; memberships, not necessarily 156 distinct cases) are now representable
without a fabricated identity:

- author the occurrence with `"typeExpectation": "not-established"` (keep its authored
  `sensitivity` and range) and seal the snapshot under schema 1.3 (the engine's
  `CorpusSnapshot::unsealed` does so automatically when a case authors it);
- the engine observes it as `unresolved` on the type axis and measures its sensitivity
  and range axes independently;
- no type-metric numerator, denominator, effective N or interval changes for the valid and
  invalid cases already carried; `jurisdiction-collision-rate` and `measurable-share`
  report the case as unresolved (counts in `unresolved`, never as pass or fail).

Distinguish in the inventory: authored uncertainty (`not-established`) is now carried;
malformed input is still refused at validation; a scanner failure is still
`failed`/`not-measured`; an unmeasured observation (an unsupported capability) is still
`not-measured`. These are different states and are not merged.

## Public synthetic example

`fixtures/contracts/v1/rev3/` (snapshot, manifest, observation, run and public artifacts):
the committed 3-case snapshot with the two occurrences of `type-card-demo` re-authored
as `not-established`, regenerated by
`PII_EVAL_UPDATE_FIXTURES=1 cargo test -p pii-eval-cli --test golden_rev3_not_established`
and byte-checked for every worker count. Hand-calculated controls:
`crates/pii-eval-kernel/tests/not_established_identity.rs` (two valid and two uncertain
cases: `type-miss-rate` counts eligible 2, measured 2, numerator 1, not-applicable 2,
total 4 against eligible 2, measured 2, numerator 1, total 2 without the uncertain cases;
`sensitive-miss-rate` 4/4/2; `measurable-share` total 8, measured 6, unresolved 2).

## Pins and upgrade requirements

Pin the engine to the merge commit of the pull request that closes this issue (record its
full SHA, and the digest of the engine binary built from it, in the benchmarks migration
record) and read schema 1.3 (`SCHEMA_MINOR` 3). A consumer that rejects unknown minors
refuses 1.3 documents by design; one that reads 1.2 must be upgraded before re-running a
population that authors the value. Documents of populations that do not author the value
remain 1.0/1.1/1.2 with unchanged bytes and digests, so existing parity results stay valid.

## What is not claimed

Upstream support does not complete the downstream migration: the benchmarks re-run all four
populations on identical inputs with a pinned oracle and this engine, update
`accepted-representable-cases` themselves, and own the scorer decision (#795) and every
threshold. The oracle's contract is closed over valid/invalid, so a dual run on these
memberships compares the engine's `unresolved` with the benchmark scorer's own
`not-established` handling, not with an oracle value.
