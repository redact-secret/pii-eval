# Handoff: authored not-established identities and ranges (issue #32)

Audience: redact-secret-benchmarks (#664, #665, #666, #795, #796). Public synthetic
development only; no protected corpus, key, policy activation or authority change. The
semantic decisions are [ADR 0017](../adr/0017-not-established-type-identity-and-schema-1-3.md)
(identity, schema 1.3) and [ADR 0018](../adr/0018-not-established-range-and-schema-1-4.md)
(range, schema 1.4). The machine-readable handoff is
[populations-32/handoff.json](populations-32/handoff.json).

## What the 156 memberships are

The 156 of 1,188 population memberships (four populations; 110 distinct cases) that the
schema 1.2 dual run left to the benchmarks' own scorer are authored with identity
`not-established`, sensitivity `not-established` **and no candidate range**. Schema 1.3
(ADR 0017) stated only the identity and still required a range, so it did not carry them;
this was found while inventorying the memberships for the regeneration and is corrected
here. Schema 1.4 (ADR 0018) states the absent range explicitly.

| Population | Memberships | Carried before | Carried now | By family (email, iban, network-address, payment-card, phone, us:ssn) |
| --- | --- | --- | --- | --- |
| oracle-plan | 146 | 95 | 146 | 9, 13, 3, 5, 16, 5 |
| qualification-plan | 266 | 230 | 266 | 9, 9, 1, 11, 4, 2 |
| diagnostic-balanced | 477 | 428 | 477 | 13, 16, 6, 11, 2, 1 |
| benign-heavy-stress | 299 | 279 | 299 | 4, 7, 6, 0, 3, 0 |

Twelve of the 156 have a built (generated) span but no authored candidate; they are carried
range-less too, because the authors' `candidate: null` is the authored fact and the engine
does not promote a generated span to ground truth.

## How to author them

- No `range` key, `typeExpectation: "not-established"`, `sensitivity: "not-established"`,
  `contextClass: "neutral"`, and the case `method: "schema-only"` (the validator refuses any
  other combination with `range-not-established-invalid`). Keep the case and its text.
- Seal the snapshot under schema 1.4 (`CorpusSnapshot::unsealed` does so when an expectation
  has no range); the run manifest must list the `schema-only` method.
- The frozen observation keeps its findings for these variants as they are; the engine does not
  read them as evidence about the occurrence and still accounts for them as unmatched spans.
- The oracle's input stays closed over located valid/invalid cases: do not export them to it.
- [populations-32/benchmarks-converter.patch](populations-32/benchmarks-converter.patch) is the
  exact change to `scripts/lib/pii-population-conversion.mjs` used for the regeneration (the
  converter is the benchmarks' own; apply it or write the equivalent).

## What the engine reports

Per range-less occurrence: type `unresolved`, sensitivity `unresolved`, range `unresolved`,
action `not-measured` (or all `not-measured` when the scanner did not complete, cannot report
ranges, or lacks a capability, as for every occurrence). Never a pass or a fail. No numerator,
denominator, effective N or interval of a located occurrence changes (the five judged metrics
equal the 1.2 dual run on all four populations: `type-miss-rate` 43/79, 15/191, 143/356,
179/247 for the oracle-plan, qualification-plan, diagnostic-balanced and benign-heavy-stress
populations). `measurable-share` now counts the uncertain samples as `unresolved`, so its
denominator grows (for example oracle-plan 148 of 292 against 148 of 190); how a scorer reads
that is #795.

## Pins and upgrade requirements

- Engine: the merge commit of the pull request that carries this file; its full SHA and the
  digest of the CI artifact `pii-eval-engine-<commit>-linux-x86_64` are recorded in the
  issue #32 handoff comment (the SHA of a commit cannot be written inside the commit). `Cargo.lock`
  SHA-256 `e646a917c7dc8a5d5f5744bbfc56456661ebeb5505ac18788b7d5262f29a956a` (unchanged).
  Build: `cargo build --release --locked -p pii-eval-cli`.
- Read schema 1.4 (`SCHEMA_MINOR` 4). A consumer that rejects unknown minors refuses a 1.4
  document by design (`schema-minor-too-new`); a reader of 1.3 or older must be upgraded before
  the four populations are re-run. Populations that author neither value stay 1.0 to 1.2 with
  unchanged bytes and digests, so existing parity results stay valid.
- Regenerated populations (semantic digests, host independent by contract) are in
  `populations-32/handoff.json`; `replay-populations.mjs` there reproduces them from the
  converter output with any engine binary (`validate` exits 0, three replays byte-equal).
  The values were measured on a local darwin build: a verification, not an official run. The
  linux replay with the pinned CI artifact is the benchmarks' step (#665).

## What is not claimed

Upstream support does not complete the downstream migration: the benchmarks re-run all four
populations on identical inputs with a pinned oracle and this engine, update
`accepted-representable-cases` themselves, and own the scorer decision (#795), the
denominator basis, every threshold and the authority (#666). The oracle's contract is closed
over located valid/invalid, so a dual run on these memberships compares the engine's `unresolved`
with the benchmark scorer's own `not-established` handling, not with an oracle value.
